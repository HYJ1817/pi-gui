# 日常使用（键盘、草稿、状态说明）

P24 收敛的是「每天真的在用」的那一层：**少点几次鼠标、别丢字、出错时知道下一步**。
这一篇记的是设计理由与边界；每一条背后都有一个具体的使用场景。

## 一、命令面板

`Ctrl+K`（macOS `⌘K`；浏览器里 `Ctrl+K` 可能被地址栏吃掉，所以另绑了
`Ctrl+Shift+P`）打开一个搜索框 + 动作列表。

**面板只暴露已经存在、且当前 context 真的能执行的动作。**

| 规则 | 为什么 |
|---|---|
| 每个命令的 `run` 都是**既有 handler**（`newSession` / `openPlanner` / `stop` / `reloadPi` / `openDiagnostics`…） | 面板里再实现一遍「切视图」「重启」，就等于有第二份真相；两份真相迟早会漂 |
| `when()` 为假的动作**不进列表**（不灰着骗人） | 灰着的项目点了没反应，比没有这一项更让人怀疑「是不是坏了」 |
| 危险动作**收敛到唯一入口**：`restartPi()` 带确认，More 菜单 / 命令面板 / 状态条三处都走它 | P24 给「重启 pi」加了两个新入口。三处各写一遍确认，迟早有一个漏掉 —— 那「有确认」就是假的。面板也**不提供**任何跳过确认的参数 |
| 打开与关闭由 `shortcuts.js` 统一管 | 加一个键盘入口就要多一处冲突可能，P24 起只有一个 `document` 监听器 |

动作分组（视图 / 会话 / 执行 / 全局）与搜索排序（前缀 > 词首 > 子串 > 子序列）
在 `public/palette-model.js` 里，**不碰 DOM，能离线单测**（`tests/daily-use.cjs`）。
「切换到会话 X」这类动态条目**只在输入查询之后才出现** —— 否则一打开面板就被
十几条会话刷屏，常用动作反而要往下找。

**没有的功能不加命令**：面板里找不到「云同步」「市场」「Fleet」这类入口，
因为它们本来就不存在。

可见入口：More 菜单（`⋯`）里的「命令面板…」与「键盘快捷键…」。快捷键要能被发现 ——
只写在文档里的快捷键等于没有。

## 二、快捷键注册表

`public/shortcuts.js` 是**全应用唯一的键盘入口**。P24 之前键盘处理散在四处
（`app.js` 的输入框 keydown、`modal.js` 的 capture 监听、`app.js` 的 Escape 分支、
`conversation-nav.js`），加一个键位要去猜「有没有人已经占了」。

```js
registerShortcut({ id, combo: 'primary+k', label, group, when, run });
assertNoConflicts();   // 装配末尾跑一次：同一个组合绑两次 → 启动就炸
```

| 键位 | 动作 | 备注 |
|---|---|---|
| `Ctrl/⌘ + K` | 命令面板 | 备用键 `Ctrl/⌘ + Shift + P`（浏览器里 Ctrl+K 常被地址栏吃掉） |
| `Ctrl/⌘ + /` | 快捷键帮助 | 内容直接从注册表渲染，不存在「文档忘了更新」 |
| `Alt + 1..4` | 对话 / 任务 / 文件变更 / 扩展与能力 | 视图切换 |
| `Enter` / `Shift+Enter` / `Esc` | 发送 / 换行 / 停止或关闭浮层 | **不在注册表里**，见下 |

**为什么 `Enter` / `Esc` 不进注册表**：它们的语义是**上下文相关**的
（Esc 在输入框、弹层、面板里各做各的事；Enter 在弹层里不能触发危险确认）。
硬塞进一张全局表只会让它们互相打架。帮助面板把它们单列一段，说明「这些键也存在」。

### 不抢普通文本输入

规则只有一句：**焦点在 input / textarea / contenteditable 里时，只有带
Ctrl/Alt/Meta 的组合才会触发。**

- `k`、`?`、空格 → 是「打字」，一律让给输入框；
- `Ctrl+K`、`Alt+1` → 照常生效 —— 这些最常见的用法，恰恰是用户正在写消息时按的。

（`inInput: true` 是给「确实要在输入框里用普通键」准备的逃生口，目前没有人用。）

### 与弹层的关系

`modal.js` 的 TrapTab / Esc 用 `capture: true`，注册表用默认的冒泡阶段。
所以弹层开着时：**弹层先处理并 `stopPropagation()`**，「Esc 关弹层」永远优先于
任何全局绑定。面板本身也不在弹层开着时抢键位（`when: noOverlay`）。

## 三、未发送草稿的恢复

### 存什么

**只有一段纯文本**：`{ v: 1, text, at }`。

明确**不存**：

- 附件对象 —— 它们带着 `dataUrl`（整张图的 base64）、`text`（抽取出来的正文）、
  `path`（本机绝对路径）。那是二进制与用户数据，不属于 `localStorage`；
- 任何 token / cookie / 网页内容 / MCP-OAuth 凭据引用；
- 会话文件的绝对路径 —— key 里用的是**哈希**，不是路径原文。

`tests/smoke.cjs` 的 P24 段直接断言「写进去的 JSON 只有这三个字段」，
`tests/cdp-shot.cjs` 的 `186` 场景在**真实 Chrome 里刷新页面**再验一次。
以后谁想往草稿里塞附件，这两条当场红。

### key 怎么组成

```
pi-gui.draft.v1:<workspaceHash>:<sessionHash>
```

- `workspaceHash` = 当前项目路径的 FNV-1a（**不是路径原文**）
- `sessionHash` = pi 会话 id 的哈希；拿不到身份时是 `nosession`
- `v1` 是格式版本：将来改结构时能一次性丢弃旧格式，而不是把两种格式混着读

### 什么时候写、什么时候清

| 时机 | 行为 |
|---|---|
| 输入 | 防抖 400ms 写一次 |
| 关页面 | `beforeunload` 里 flush（防抖窗口里的最后几个字不该丢） |
| 发送成功 | 清掉当前身份的草稿（否则刷新后会把已发出的内容再填回来，像「发重了」） |
| 手动清空输入框 | 空文本**不落盘**，同时删掉旧 key（不留幽灵草稿） |
| 换项目 / 换会话 | 旧身份的字先归档，再读新身份的草稿 |
| 上限 | 单条 20000 字符，超出部分不存 |
| 存不下（隐私模式 / 配额满） | 静默降级为「不持久化」—— 功能照常，只是刷新后不恢复，**绝不弹错** |

### 换身份时的边界（容易出错的地方）

输入框里可能有一段「用户刚打、还没归档到任何身份」的字。这种情况下换身份
**不许**用旧草稿覆盖它 —— 覆盖就是真的丢字。规则：

- 输入框是空的，或者内容等于「我们上一次归档的值」→ 用新身份的草稿填充；
- 否则**不动它**，下一次输入会把这段字归到新身份。

这条规则由 `tests/smoke.cjs` 的「换会话后输入框换成新会话的草稿」「切回原会话 →
原文恢复」「换项目不会串到上一个项目的草稿」三条覆盖。

## 四、启动 / 连接状态说明

P24 之前，「正在启动 pi…」「pi 已退出」「兼容性有问题」「没选项目」散在四五处，
各自一套措辞：同一件事在状态栏是一句话、在 toast 里是另一句、在诊断里是第三句，
用户没法把它们当同一件事读。

现在文案只有一份来源 `public/status-copy.js`：

```js
connectionCopy(state)   // 底部连接指示的标签与语气
startupNotice(ctx)      // 需要**常驻**的启动/连接问题 → null 或一条 notice
SURFACE_COPY            // 七个页面共用的 loading / empty / failed / retry
```

### 哪些状态会常驻

| 状态 | 常驻？ | 为什么 |
|---|---|---|
| pi 启动失败 | ✅ 带后端的 `error` + `hint`，动作：重启 Pi / 打开诊断 | 它会一直在；toast 会消失，用户回来时得还能看到 |
| pi 已退出 | ✅ 同上 | 同上，而且要说清「当前无法继续发消息」 |
| 关键能力不可用（`incompatible`） | ✅ 只给「打开诊断」 | 能力缺失是**持续**的，不是一次事件 |
| 正在启动 / 正在重启 | ❌ | 输入区已经锁住并给了解释，再挂一条是噪声 |
| 已连接 | ❌ | 正常状态不该占用界面 |
| 没选项目 | ❌ | 欢迎区已经在说这件事，两处说是重复 |

### 边界：给下一步，但不自动修

状态条只做两件事：**说清现在是什么状态**、**把用户送到已有的入口**
（重启 = `restartPi()`，诊断 = `openDiagnostics()`）。

### 重启 pi 的唯一入口与确认

`restartPi()`（`app.js`）是**唯一**的重启入口，三个地方都走它：More 菜单的
「重启 pi」、命令面板的「重启 Pi」、状态条的「重启 Pi」。

确认框按「会不会真的中断什么」分开写话：

- 正在生成 → 「正在生成回答，重启会中断这一轮。」
- 空闲 → 「重启会重新加载配置并重建会话视图。」

两者都补一句「磁盘上的会话与文件不受影响」—— 这是用户按下去之前真正想知道的。
`S.streaming` 为真时，确认框用的是同一套 `confirmModal`（危险按钮需要显式点击，
键盘 Enter 不会替用户按下去）。

面板与快捷键**都不提供跳过确认的路径** —— `tests/smoke.cjs` 的
「从面板重启必须先确认」那条断言盯着这件事。

> 模型供应商面板里的「重载配置」仍然直接调 `reloadPi()`：那是用户在
> **刚刚改完配置**的上下文里点的，语义是「让改动生效」，不是「重启一下试试」。

它**不会**自动 `chmod`、不会自动装 pi、不会改 `PATH`、不会删配置。
这类「自动修复」在错误判断下会造成比原问题更大的破坏，而用户真正需要的是
一句能照着做的说明。

### Native MCP 的 disabled / replaced / unknown

这三个状态**不在这条状态条里** —— 它们是 MCP 这一个子系统的状态，说明在
MCP 标签页与能力视图里（原生状态 + 两处 mcp.json 的结构 + 运行时状态），
诊断面板里也有一份。放进全局状态条只会让「pi 起不来」这种真问题被淹没。
统一的只是**措辞与视觉**，不是把所有状态挤进一个组件。

## 五、加载 / 空 / 失败 措辞统一

`SURFACE_COPY` 把七个页面（Chat / Planner / Changes / Extensions / Capabilities /
MCP / Usage）的固定话术收成一份：

| 语义 | 文案 |
|---|---|
| loading | `正在读取<对象>…` |
| empty | `还没有<对象>。` |
| failed | `<对象>读取失败。` |
| retry | `重试` |

**Retry 只在真的有重试路径时出现。** P24 补的是「扩展发现失败」那一处
（它的重试路径就是同一个 `load()`）；其余没有重试路径的地方**不给按钮** ——
一个点了没反应的按钮比没有按钮更糟。

## 六、无障碍

- 每个 `dialog`（设置、诊断、确认、命令面板、快捷键帮助）都有
  `role="dialog"` + `aria-modal` + 焦点移入 + 关闭后**焦点还原**；
- `Tab` 在弹层里循环（`modal.js` 的 `trapTab`）；面板只有一个输入框，
  `Tab` 留在它上面；
- `Esc` 关闭当前最上层的东西（capture 阶段，弹层优先）；
- 焦点环**不做删除**：`button / input / select / textarea / [role=button]` 有全局
  `:focus-visible`，面板条目另有内嵌环；
- 状态条用 `role="status"`（错误时 `role="alert"`），关闭按钮有 `aria-label`。
