## 实施方案与边界

现有 `workspace-surface` 保留中央对话、Planner 与扩展的实例生命周期。
`right-pane` 负责互斥工作面和空间释放，`secondary-surface` 负责 Changes 的挂载与
过期异步结果失效；Browser 切走时卸载原生 WebContentsView，关闭不保留空壳。
Settings 使用已有可发现的全局入口，按六组组织真实动作，没有新增配置源。
更新复用 `update.js` / `pi-update.js`；Provider/Auth、MCP、诊断仍使用原 owner。

保留 52px 全局导航与项目树的既有结构，避免破坏侧栏折叠后的全局入口。
Planner 已有完整任务/审阅/验证流程，保留一级任务入口；仓库没有“确实日用”的统计证据。
Review 继续放在 Planner 详情：复杂的审阅、门控与验证表单沿用现有承载，未新增空 Preview 按钮。
Capabilities / MCP 过滤器仍在扩展页面内可访问；设置的分组入口复用同一个模块与过滤器。

## 实施与验证顺序

1. 只读核对 main、README/docs、入口装配、项目会话与弹层、现有 UI/harness；输出审计。
2. 完整基线；新建分支；新增组装 UI 行为回归并确认旧行为失败。
3. 移动入口，保留真实 handler；右栏互斥、焦点、异步生命周期；最后调整有限 CSS。
4. 更新旧测试中 Changes 的容器/语义，保留原 Diff/撤销覆盖与断言数量。
5. npm test；offline visual harness；三个分辨率和关键状态、键盘与缩放；Electron 检查。
6. 离线重建 SEA/Electron，验证产物；按回滚边界提交，不推送、不合并、不发版。

验收数字、截图与限制记录在 `docs/p30-acceptance.md`。
