在合并后，必须取得 main 上的精确提交 SHA，并确认其 push CI 成功：

```powershell
# 1. 拉取最新远端状态
git fetch origin

# 2. 获取合并后最新 main 的完整 SHA
$targetSha = (git rev-parse origin/main).Trim()
Write-Host "最新 main 提交 SHA: $targetSha"

# 3. 查询该 SHA 对应的 main push CI 运行 ID
$runId = (gh run list --workflow=ci.yml --branch main --commit $targetSha --json databaseId -q '.[0].databaseId').Trim()
Write-Host "CI 运行 ID: $runId"

# 4. 观察并等待 CI 完成（返回成功状态码）
gh run watch $runId --exit-status
```

*若无 gh CLI，可在浏览器访问 https://github.com/HYJ1817/pi-gui/actions ，点击最新的 `CI` 运行，核对提交 SHA 是否与 `$targetSha` 一致，并确认所有 Job（包括 `CI gate`）均为绿色的对勾（Success）。*

### 阶段 5：正式打 Tag 并发布

只有在满足以下全部 6 项条件后，方可创建并推送正式 tag：
1. 指向的 SHA 已包含 Node 24.22.1 与版本号 0.28.0 准备提交。
2. 该提交已合并入最新 `origin/main`。
3. `package.json` 声明版本为 `0.28.0`。
4. 同一 SHA 的 main push CI 全部成功。
5. `ci-gate` 成功。
6. 用户明确批准发版。

```powershell
# 1. 确保使用最新 origin/main 对应的 commit
$targetSha = (git rev-parse origin/main).Trim()

# 2. 创建带附注的正式发布 tag（直接指向已验证的 main SHA）
git tag -a v0.28.0 $targetSha -m "发布：pi-GUI v0.28.0"

# 3. 推送 tag 到 GitHub（触发 release.yml 自动化发布工作流）
git push origin v0.28.0

# 4. 观察 Release 工作流运行
# 先获取 release 运行 ID
Start-Sleep -Seconds 5
$releaseRunId = (gh run list --workflow=release.yml --limit 1 --json databaseId -q '.[0].databaseId').Trim()
gh run watch $releaseRunId --exit-status
```

*发布成功后，可访问 https://github.com/HYJ1817/pi-gui/releases/tag/v0.28.0 核对正式发布的资产（Setup.exe、portable.zip 与 SHA256SUMS.txt）。*
