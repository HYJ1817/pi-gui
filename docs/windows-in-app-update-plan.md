# Windows 应用内更新实施记录

基线：31e7f71，v0.26.2。独立分支 codex/windows-in-app-update，禁止推送、合并和发版。

复用现有 `/api/update`、安全 Markdown、Electron preload、Runtime 清理屏障和 NSIS。新增依赖为零。

- [x] 先写离线状态机测试，覆盖官方资产绑定、SHA256、取消/重试、缓存恢复、模式降级和忙态拒绝。
- [x] 主进程控制下载与安装；Renderer 只发送具名动作，不能提供路径、URL 或执行参数。
- [x] 后端通过私有父子 IPC 获取维护锁，拒绝活动任务；冻结新写请求，确认 Runtime 与 pi 退出。
- [x] 外部 PowerShell helper 等待进程句柄退出，复验安装包，备份应用目录，静默安装、验证版本、失败恢复程序文件并重启。用户数据不参与备份或替换。
- [x] NSIS 静默安装遇到运行实例直接失败，禁止隐藏确认框或强杀。已有交互安装流程保留。
- [x] 设置区复用现有布局，说明独立滚动、固定操作区、进度速度、取消和重试、稍后与重启按钮。
- [x] 跑专项回归、真实 Electron 截图、隔离 NSIS 升级；记录未验证项并独立功能/安全复审。

安全策略：任何运行/审批/认证/工具/进程或未完成请求存在时拒绝重启，提示先等待或停止任务；第一阶段不提供强制终止入口。安装识别必须匹配当前 exe 与 HKCU 安装记录及卸载程序，不能仅凭 packaged 或目录名猜测。网络仅用户点击下载后读取官方 Release 资产，不携带本地凭据。GitHub 公开 Release SHA256 经 HTTPS 获取，不能抵御官方账号本身被接管；不改变现有签名流程。

验证必须仅操作 os.tmpdir 内 fixture。原有 installer-check 写真实默认安装位置，本次不运行，另写隔离测试使用独立安装身份和目录。

完成证据见 docs/windows-update-evidence/REPORT.md。签名后的公网下一版升级仍待正式发布前验证；不把本地候选包当作正式发布资产。
