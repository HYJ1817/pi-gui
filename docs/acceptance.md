# 开发验收材料

本文只规定开发者如何组织、定位和提交证据。审查标准、风险等级、发现处置及合并门槛
唯一依 [REVIEW.md](../REVIEW.md)；开发硬约束与操作授权依 [AGENTS.md](../AGENTS.md)。
测试执行政策依 [testing.md](testing.md#测试执行政策)，正式发布唯一流程依
[releasing.md](releasing.md)。本材料规范不改变上述政策，不是产品内 Planner 的人工审阅规则。

## 报告内容与提交身份

日常报告使用下方精简模板即可；每项给出结论、证据位置或不适用的原因，无需粘贴整份日志。
至少覆盖：

1. 任务目标、实际交付范围及明确未交付项。
2. 基线提交 SHA（before HEAD），分支与必要的工作区差异。
3. 最终交付提交 SHA（after HEAD），并指出各项证据实际覆盖的提交。
4. 实际修改文件及用途，可附准确范围的 `git diff --name-status` 输出。
5. 功能行为变化；纯文档明确写无产品行为变化。
6. 关键安全边界及其保留或变化情况。
7. 实际测试命令、环境、退出码、套件/断言数量与日志位置。
8. 首次失败、取消、跳过、修复及重跑历史；没有则写无。
9. UI 或 Electron 实测场景、截图和产物位置；不适用则说明。
10. 已知限制、未验证项及残余风险。
11. 可执行的回滚方式及数据/产物恢复边界。
12. 待用户决定事项，以及开发、验收、合并和发布各自的状态。

SHA 应可精确定位，不能只写“最新 main”。提交前的工作区验证记录 HEAD 加待提交 diff；
提交后核对实际文件树。行为提交之后仅补报告时，分别列行为 SHA 与报告 SHA，不将旧运行称作新 SHA 的 CI。
报告随提交进入仓库，无法在自身内容中写入包含自己的提交哈希：可把最终 SHA 定义为
“包含本报告的交付提交”，提供 `git log -1 --format=%H -- docs/<本报告文件名>.md` 的解析命令，
并在最终交付消息写出实测 SHA。后续修改报告时保留原交付 SHA，避免命令悄悄指向新的验收范围。

## 证据分层

按来源和环境分别记录；同一运行可带多个标签，但各自的结论不能互相代替。

| 证据 | 应记录什么 | 不能据此推定 |
| --- | --- | --- |
| 作者自测 | 作者、提交/工作区差异、命令与实际结果 | 已独立审查或用户已接受 |
| 独立代码审查 | 审查者/独立上下文、精确 diff、发现与处置、未检查范围；报告格式引用 REVIEW | 测试已运行或已获操作授权 |
| 本地定向测试 | 命令、受影响套件、环境、退出码、实测数量 | 完整 canonical 已通过 |
| 本地完整 canonical | 当次 `npm test` 的代码状态、日志、退出码及数量；中断续跑按 testing 标注累计验证 | PR/main CI 或专项环境通过 |
| PR CI | run URL/ID、event、attempt、head/merge SHA、实际检查范围与 gate | 发布提交的 main push CI |
| main CI | run URL/ID、push event、attempt、精确 SHA、完整范围和 gate | 新提交或打包/安装升级已验证 |
| Electron 实测 | 源码/打包入口、Electron 版本、沙箱模式、fixture、交互、窗口尺寸和截图 | 打包产物一致、真实 Pi/模型或正常沙箱通过（若使用了 `--no-sandbox`） |
| 打包产物检查 | 构建命令、源码 SHA、产物版本/路径/摘要与实际运行结果 | 真实安装或原位置升级成功 |
| 真实模型测试 | 明确授权范围、模型/供应商、真实调用与结果；保留脱敏摘要 | 默认离线 canonical、其他模型或安全资格通过 |
| 真实安装升级测试 | 隔离环境、旧/新版本、安装目录、升级/卸载过程、恢复结果 | CI 新装等同原位置升级，或任意环境均通过 |

未运行写「未验证（未运行，原因）」；运行失败、取消、中断、skip 均不能写通过。
套件数与断言数分开，skip 不计入通过分子分母；数量只来自实际输出，不能编造或套用历史报告。
数量减少须说明少了哪些断言。完整证明的选择、复用、变化后补验规则直接依 testing，不在这里另设政策。
日志只保留必要摘要或链接，遵守 [security.md](security.md) 的隐私边界，不归档密钥、用户正文或原始 payload。

## 按既有风险等级组织材料

等级与最低审查要求直接依 [REVIEW 第 2 节](../REVIEW.md#2-按变更风险决定审查力度)，混合变更按该节处理。
以下仅是证据示例，不增设评级或降低门槛；不适用的证据说明原因，不能据示例跳过必要验证。

| REVIEW 等级与场景 | 材料示例 |
| --- | --- |
| 低：文档、无行为影响的整理 | diff、相对链接/锚点检查、事实与职责一致性；说明跳过完整测试的依据 |
| 中：常规功能、UI | 作者验证、独立审查记录、相应回归与约定完整 canonical；UI 附真实交互/截图 |
| 高：身份、写入、Git/权限、恢复、CI、更新与发布等边界 | 精确身份与授权范围、独立功能/安全审查、故障注入、环境与产物专项、失败后的状态和恢复/回滚证据；受限项与用户明确决策单列 |

例如后续 T4-C 若交付真实文件写入，材料还需覆盖来源/目标身份、并发或事务冲突、写入中断、
部分失败、恢复与用户改动保护。只读预检或 Diff 展示不能充当写入安全证明；具体资格以该阶段实际设计、代码和验证为准。
本段不声称 T4-C 已实现写回，也不授权执行真实项目写入测试。

## 可复制的精简报告

以下占位项必须替换为事实；无关项写不适用及原因，未执行项写未验证。大型安全阶段按需附故障矩阵与日志索引，
历史验收文档保留原位置与提交范围，不要求批量迁移。

```markdown
# <任务> 验收材料

- 目标与交付：<完成范围；未交付项>
- 身份：before HEAD <完整 SHA>；after HEAD <完整 SHA 或本报告交付提交的解析方式>；分支 <名称>
- 证据范围：<实际验证 SHA / 工作区 diff；仅补报告的后续提交单列>
- 修改文件：<路径及用途，或 diff 清单>
- 行为与安全边界：<变化；保留的身份/审批/数据边界；纯文档说明无行为变化>
- 风险：<依 REVIEW 的低/中/高及原因>

| 证据层 | 命令/场景与代码状态 | 环境、退出码与实际结果 | 日志/截图/run |
| --- | --- | --- | --- |
| 作者自测 / 本地定向 | <命令或不适用原因> | <套件、通过/失败断言、单列 skip> | <位置> |
| 本地完整 canonical | <npm test 或未验证及原因> | <实际结果> | <位置> |
| 独立审查 | <审查者、diff；按 REVIEW 报告> | <结论、发现及逐项处置> | <位置> |
| PR CI / main CI（分别记录） | <各自精确 SHA/event/attempt 或未验证> | <范围与 gate> | <run URL> |
| Electron / 产物 / 模型 / 安装升级（逐项记录） | <实测或未验证/不适用及原因> | <实际结果与限制> | <位置> |

- 失败与修复历史：<首次失败、原因、修改、重跑；无则写无>
- 限制与残余风险：<未验证平台、边界和环境>
- 回滚：<回退哪些提交；数据/产物如何恢复；保留其他工作>
- 待用户决定：<事项；无则写无>
- 结论：开发完成 <状态>；代码验收 <状态>；合并许可 <状态>；发布许可 <状态>
```

## 结论与授权

“开发完成”“代码验收通过”“允许合并”“允许发布”的含义直接引用
[REVIEW 第 5 节](../REVIEW.md#5-验证与合并准则)。报告分别填写这四项，不重新定义门槛。
独立审查意见与用户授权分别记录；测试全绿不会自动允许推送、合并或发布。
本地提交、推送、合并、tag 和发布依 AGENTS 的各自授权边界执行。
