# 会话后台执行与自由查看

基线 main eb39982。复用现有 Runtime Registry / runtime-state / runtime-conversation / worktree admission。

已确认：普通 Pi 子进程的 switch_session 会替换并中断原执行线；独立 Runtime 有固定 cwd、owner、停止屏障、审批和持久记录，但默认禁止两个执行线占用同一个工作区。不得删除此限制来伪造安全并发。

执行范围：

1. 增加通过稳定 session ID + 已登记项目查找的只读历史接口，复用有界 same-fd 历史读取与 header 身份校验；查看不调用 Pi。
2. 执行中普通会话/项目点击只切视图，保留经典聊天 DOM 和执行状态；可返回原会话。其它会话可先编辑草稿，当前目录的执行仍等到原执行线空闲后才交接。
3. 执行中新建会话提供草稿及既有独立工作区 Runtime 创建入口；安全并发继续走独立工作区，不复制/搬迁原生会话、不改变 Pi schema、不自动批准或 Stop。
4. 将经典审批挂起展示与协议取消分开；离开视图不取消，后台待审批有入口，回到原会话可继续处理。Runtime 审批/Stop 沿用原有 captured owner。
5. 后端保留并补齐执行中切换/新建保护，防止 UI 之外的请求意外中断任务。
6. 定向验证：A/B 查看与快速切换、后台完成、独立 Runtime 并发/停止/审批和 owner、跨项目、历史恢复；真实 Electron 与离线打包。按用户的时间约束，不再跑全量 npm test。

边界：同一目录的两个普通历史会话不直接同时执行；并行必须使用已有独立工作区流程。这是本轮明确允许的分阶段安全路径，不能宣称任意普通会话已经具有隔离并发。
