# 普通会话同目录并发

用户已确认：普通会话任务并行，同目录写入工具排队；不以 worktree 替代普通会话，不仅删除 busy/lease 判断。基于功能分支 cfcbe01 继续，原有未跟踪目录保留。

复用 Runtime Registry、独立 RPC 子进程、owner、资源上限、审批/停止屏障、native session scanner 和现有 Runtime 视图。新增普通项目绑定，不改 Pi 本体、schema、账户配置或模型 API，不自动批准。共享目录不是 OS sandbox，外部终端和扩展自身的旁路副作用仍不能被声明为已隔离。

步骤：

1. 有界、公平的工具写入队列：按真实目录及重叠路径协调；读工具仅在官方来源可证明时旁路；未知工具和 shell 保守当写入；嵌套调用可重入。取消等待不释放仍执行的写入，清理不确定时保持封闭。
2. 每次 Pi 启动分配独立私有能力与扩展，通过真实原生 session 回读完成握手。主会话和新 Runtime 都必须接入；缺少可证明的工具守卫时拒绝共享目录并发。
3. 普通项目/历史会话在后端按登记路径、稳定 ID、文件/header 身份绑定到独立 Runtime。相同 native session 不允许被主会话和另一个 child 同时打开；不同会话共享目录仅在守卫就绪时允许。
4. 现有会话/新会话入口直接进入所属 Runtime，可发送任务，不要求新建工作树；消息、审批、Stop、Token、草稿与恢复继续使用完整 owner。
5. 针对队列、协议、同目录双 child、停止等待、迟到应答、项目隔离、恢复和真实窗口分别验证；重建产物。按用户要求不跑全量 npm test，不推送/合并/发版。

ADR 0032 的默认 worktree 独占策略保持为隔离模式；本轮新增经工具守卫证明的共享项目模式，不能沿用旧的“最多一条 GUI 写执行线”结论宣称已经禁止所有同目录并发。
