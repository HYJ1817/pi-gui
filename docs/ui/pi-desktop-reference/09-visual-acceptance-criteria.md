# 09. 视觉与功能验收规范 (Visual & Functional Acceptance Criteria)

> 本文用于复核 PI-Desktop 参考与当时的改造阶段。当前开发与验收见 [pi-GUI 全局 UI/UX 设计规范](../design-system.md)。

> **审计与验收原则修订 (Audit Revision)**：
> 1. **事实与估算边界澄清**：参考截图的图像物理像素尺寸（`1808 × 1204` / `1808 × 1205` PNG）属于已确认的客观事实；但捕获时的系统 DPI、OS 缩放比例（100% vs 125%）、实际 CSS 逻辑视口及渲染器配置，在未获得实测元数据前严格标为**待实测估计值 (Unconfirmed Estimates)**，禁止当作绝对技术前提。
> 2. **排除无业务支撑的虚假控件验收**：与功能映射矩阵（`07-pi-gui-gap-analysis.md` 类别 C）保持完全一致——对于 pi-GUI 尚未实现的 JEV 实时语音通信（`REF-006`）、第三方在线技能市场（`REF-009`）及独立子智能体声明抽屉（`REF-011`），**明确标为“不予实现 / 排除验收”**。严禁为了追求截图覆盖率而在界面上伪造无后端支撑的假开关、假输入框或空网格！
> 3. **浅色主题验收双轨制**：在提供的 24 张参考截图中，仅有 4 张（`REF-021` 至 `REF-024`）为浅色主题，其余 20 张均为深色主题。对于缺少浅色截图的页面，**严禁宣称已完成直接截图像素对比**，必须依据 PI-Desktop 官方源码 `:root[data-theme="light"]` 的 Token 规范与 CSS 规则进行规则级与渲染级验收。

## 1. 验收环境参数与参考截图尺度校准基准 (Calibrated Scale Baseline)

### 1.1 实测确认的客观尺度与环境参数 (Verified Facts)
经对全部 24 张原始参考 PNG 文件的二进制元数据（pHYs 块）提取，以及在实际 Electron 客户端环境中的真机实测（`scaleFactor = 1.5`, `devicePixelRatio = 1.5`），确立了严格统一的几何尺度对应关系：

- **物理像素 (Physical Pixels)**：
  - 截图物理分辨率：`1808 × 1204`（3 张）与 `1808 × 1205`（21 张）PNG 图像。
  - REF-004 设置侧栏实测物理宽度：`412.5 ~ 413` 物理像素（经真实 PNG 解码，`x=412` 为纯黑 `#000000`，`x=413` 阶跃为 `#181818`）。
- **PNG DPI 元数据**：
  - 全部 24 张截图均包含内嵌 `pHYs` 块：`5669 × 5669 pixels/meter`，换算为 **`143.9926 DPI` (≈ 144 DPI)**。
  - 依据 Windows 基础基准 96 DPI 计算：`144 DPI / 96 DPI = 1.500`（系统显示缩放比例为 **150%**）。
- **CSS 逻辑像素 (CSS Layout Pixels)**：
  - 转换关系：**`1 CSS 像素 = 1.5 物理像素`**，反之 **`1 物理像素 = 0.6667 CSS 像素`**。
  - 视口逻辑宽度：`1808 / 1.5 = 1205.33` CSS 像素（对应 Electron 窗口宽 `1205px`）。
  - 视口逻辑高度：`1204 / 1.5 = 802.67` CSS 像素，`1205 / 1.5 = 803.33` CSS 像素（对应 Electron 窗口高 `803px`）。
  - 设置导轨宽度：源码 `--ds-settings-nav-width: 275px;` × 1.5 = **`412.5` 物理像素**，与实测 413px 完全吻合！
  - 顶栏标准高度：源码 `--ds-toolbar-height: 46px;` × 1.5 = **`69` 物理像素**。
  - 方形控件尺寸：源码 `--ds-control-size: 28px;` × 1.5 = **`42` 物理像素**。
  - 输入框大圆角：源码 `--ds-composer-radius: 20px;` × 1.5 = **`30` 物理像素**。
  - 用户气泡圆角：源码 `--radius-lg-plus: 18px;` × 1.5 = **`27` 物理像素**。
- **截图数量与主题分布**：
  - 全部 24 张截图中，深色主题 20 张（`REF-001` 至 `REF-020`），浅色主题 4 张（`REF-021` 至 `REF-024`）。

### 1.2 统一比较尺度与截图测量准则 (Uniform Comparison Benchmark)
后续进行视觉验收与截图比对时，遵循统一双尺度规范：
1. **真机 150% 缩放直接对比**：在与参考截图相同的 150% 缩放环境（`devicePixelRatio = 1.5`）下截屏，生成 `1808 × 1205` 物理像素截图，进行 1:1 像素级叠层或并排对比。
2. **逻辑 100% 归一化对比**：若在 100% 缩放环境（`devicePixelRatio = 1.0`）下，窗口逻辑视口应为 `1205 × 803` CSS 像素，此时物理像素与 CSS 像素等价（设置轨 275px，顶栏 46px）。此时严禁将 275px 与 413px 误判为视觉尺寸缩水。
3. **容差标准**：Windows DWM 窗口边框在不同主题和聚焦状态下可能引起 ±1px 物理浮动，不判定为阻断性缺陷。

## 2. 浅色模式双轨验收规范

### 2.1 第一轨：具有直接参考截图的页面 (Direct Screenshot Matching)
包含：`REF-021` (对话主视图), `REF-022` (斜杠补全), `REF-023` (上下文检查器), `REF-024` (文件提及补全)。
- **验收方式**：在桌面端生成同分辨率实测截图，进行并排 1:1 像素与布局对比。
- **重点指标**：
  - 侧边栏为柔和浅灰 `#f3f3f3` (`--ds-bg-sidebar`)，主画布为纯白 `#ffffff` (`--ds-bg-primary`)；
  - 正文字色为高可读性深墨黑 `#1a1c1f` (`--ds-text-primary`)；
  - 浮动 Composer 纯白微阴影，发送按钮黑白反转为深墨色实心圆 (`--ds-accent`)。

### 2.2 第二轨：缺少浅色截图的页面 (Code & Spec-Driven Verification)
包含：设置中心各分类页 (REF-004, REF-005, REF-007, REF-008, REF-010, REF-012)、供应商配置弹窗 (REF-013 ~ REF-014)、工作区工作台 (REF-003, REF-018, REF-019)。
- **严正声明**：该类页面**未提供浅色模式历史截图**，严禁伪称“已通过截图对比”。
- **验收方式**：依据上游源码规格 [`07-ui-design-system.md`](https://github.com/vastsa/PI-Desktop/blob/92ae661f1e399e69d514086b46029b4c34ba1a92/docs/zh-CN/spec/04-ux/07-ui-design-system.md) 与 [`tokens.css`](https://github.com/vastsa/PI-Desktop/blob/92ae661f1e399e69d514086b46029b4c34ba1a92/apps/desktop/src/styles/tokens.css) 进行规则级验收：
  1. **背景与表面阶梯**：
     - 设置分类导轨底色必须为 `#f3f3f3` (`--ds-settings-rail-bg`)；
     - 设置卡片背景必须为 `--ds-tile` (`color-mix(in oklab, #1a1c1f 3.5%, transparent)`)；
     - 聚焦项必须抬升为纯白 `#ffffff` (`--ds-raised`) 并附带轻柔阴影 (`--ds-raised-shadow`)。
  2. **强调色与开关反转**：
     - 主按钮由暗色白底反转为深墨色底 `#1a1c1f` (`--ds-accent`)，文字为纯白；
     - 开关关闭态保持白色滑钮处于浅灰轨道 (`--ds-switch-knob-off: #ffffff`)，且外圈带有 1px 细环 (`--ds-switch-ring-off`)；
     - 开关开启态保持滑钮为纯白，轨道变为深墨黑 (`--ds-accent`)。
  3. **文本对比度标准**：
     - 正文必须满足 WCAG AA 级以上对比度（深墨色 `#1a1c1f` 在白底上达到 16.5:1）；
     - 弱化文本 `#5d5d5d` (`--ds-text-muted`) 在白底上必须达到 4.5:1 以上。

## 4. 阻断性与容忍性判定标准

### 4.1 阻断性判定 (Blocking - 一票否决)
- **视觉破绽**：出现原生 Windows 粗黑滚动条、默认天蓝色焦点光圈、生硬的 1px 亮灰分割线违背 D297 规范。
- **浅色模式失真**：浅色模式下主按钮仍为白色文字看不清、背景变白而文字仍为浅灰导致对比度不足 4.5:1。
- **业务功能丢失**：pi-GUI 原有的会话改名、对象撤销、Git 管理、Planner 步骤查看等能力在重构后无法点击或报错。
- **键盘/焦点陷阱**：在 Composer 输入 `/` 或 `@` 时，输入焦点被浮层强行剥离，导致中文输入法（IME）中断。
- **窗口控制遮挡**：右上角 120px 原生窗口控制按钮区域被内容或拖拽区域遮挡导致无法最小化/关闭。

### 4.2 允许保留的合理差异 (Tolerable Discrepancies)
- **品牌名称**：标题栏与界面文本保留 `pi-GUI` 作为产品名称，仅借鉴 PI-Desktop 的排版与交互体验。
- **后端模型列表差异**：模型下拉项展示用户本地实际配置的供应商与模型，不硬编码截图中的特定型号。
- **系统级字体回退**：中文字体在 Windows 下优先使用 `Microsoft YaHei` / `PingFang SC`，排版微量字符间距差异属于正常现象。
- **排除功能的留白**：REF-006、REF-009、REF-011 排除验收，不设置任何无功能支撑的假 UI。
