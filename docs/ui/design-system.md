# pi-GUI 全局 UI/UX 设计规范

本文是仓库唯一的全局视觉与交互规范。任何 Agent 或开发者新增、修改、优化或重构 UI 时均须遵守，范围包括设置、工作区、Classic、Runtime、工作面板和原生窗口中的产品控件。功能文档定义业务行为和状态归属，[AGENTS.md](../../AGENTS.md) 与 [REVIEW.md](../../REVIEW.md) 定义开发、权限和审查流程。

开发前从实际页面入口核对样式加载顺序、按需样式和最终生效规则，再定位组件及 Token 的所有者。文中的数值示例以默认字体缩放为准。当前渲染值用于确认实现和差距，本文定义新增与修改的目标。[主页面入口](../../public/index.html) · [运行时 Token](../../public/tokens.css) · [公共样式](../../public/ui/primitives.css) · [组件工厂](../../public/ui/primitives.js)

发现规范与现有实现冲突时，先定位层叠、继承和组件所有者，再在本次任务范围内通过共享入口处理。确需例外时，在变更说明中记录业务原因、受影响页面和状态、保留的公共规则、验收证据及后续处理方式。跨功能的例外按既有审查流程评估。

[设计系统现状审查](design-system-audit.md) 保存规范建立时的实现证据和历史发现。[全项目 UI/UX 审计](PI-GUI-UI-FULL-AUDIT.md) 保存所审计代码基线的问题、截图、待验证项及整改顺序。

## 排版

正文界面使用 `--font-sans`，继承现有系统字体和 CJK 回退，尊重外观的字体与 `--font-scale` 设置。代码、命令、模型 ID 和路径可用 `--font-mono`。常规数值列可用 `font-variant-numeric: tabular-nums`。标题保留自然的语义层级，界面字体由角色统一决定。

| 角色 | 字号 | 字重 | 行高 | 前景 |
| --- | --- | --- | --- | --- |
| 页面标题 | `--text-xl`（20px） | `--font-weight-semibold`（600） | `--leading-heading`（1.15） | `--ds-text-primary` |
| 分组标题 | `--text-lg`（16px） | 600 | `--leading-tight`（1.25） | 主文字 |
| 表单标签、列表主标题 | `--text-md`（13px） | `--font-weight-medium`（500） | `--leading-compact`（1.3） | 主文字 |
| 表单控件、菜单和紧凑操作 | `--text-sm-plus`（12.5px），沿用通用设置 Select 的 `--text-md`（13px） | `--font-weight-normal`（400），主动作 500–600 | `--leading-normal`（1.4） | 主文字或次级文字 |
| 说明与正文 | `--text-base`（14px） | 400 | `--leading-body`（1.45），长正文用 `--leading-prose`（1.6） | 主文字，辅助信息用次级文字 |
| 次要信息、状态徽标 | `--text-sm` / `--text-xs`（12 / 11px） | 400 / 500 | `--leading-normal`（1.4） | `--ds-text-secondary` / `--ds-text-muted`，状态搭配语义色 |

同角色字号与字重随公共实现收敛。空间紧张时先换行、调整布局或把次要动作收入现有菜单。截断长路径或标识时保留键盘可获得的全文或复制入口。错误、字段要求和关键状态使用能在实际表面上读清的文字色。

## 色彩与主题

| 用途 | 首选语义 Token |
| --- | --- |
| 画布与面板 | `--ds-bg-primary` / `--ds-bg-secondary`，侧栏、Dock 和 Composer 用现有专用表面 |
| 内流卡片和行 | `--ds-surface-card` / `--ds-tile` |
| 输入与浮层 | `--ds-surface-input` 或现有 `--ds-field-inset-bg`，浮层用 `--ds-bg-elevated-opaque` |
| 正文、次级、弱化 | `--ds-text-primary` / `--ds-text-secondary` / `--ds-text-muted`，`--ds-text-faint` 只用于可弱化且已实测对比度的内容 |
| 边界 | `--ds-border-default`、`--ds-border-input`；确需增强时用 `--ds-border-strong` 并验证 |
| Hover / Pressed / Focus | `--ds-bg-hover` / `--ds-bg-active` / `--ds-focus`，选中用已有选中语义和状态标记 |
| 主动作 | `--ds-accent` / `--ds-accent-hover`，前景选择与实测表面相配的语义色（现有发送键使用 `--ds-bg-primary`） |
| 成功、警告、失败、信息 | `--ds-success`、`--ds-warning`、`--ds-error`、`--ds-info` 与对应 `-surface`，配文字或可识别图形 |
| 浮层与遮罩 | `--ds-shadow-popover` / `--ds-shadow-dialog`，遮罩用 `--ds-scrim` 或现有 `--ds-modal-veil` |

深浅主题通过根 `data-theme` 和 `color-scheme` 切换。复用 [首屏解析](../../public/theme-init.js)、[Web/renderer 主题接口](../../public/theme.js) 和 [Electron 主题桥](../../electron/theme.cjs)，保留系统模式、原生窗口同步和主题优先级。新样式优先取公共语义 Token。 `--ui-*`、`--focus-ring` 和短名变量仍服务既有消费者。需要补齐语义时在共同所有者定义一次，并核对两个主题及相关调用方。禁止把调色板原始色值或自定义暗色规则散到页面里。终端 ANSI、图表数据系列、外部网页及隔离窗口的安全边界沿用各自所有者，需按场景验收。

按 WCAG 2.2 AA，启用控件的 placeholder、辅助说明、正文和状态文字都必须可读。普通文字至少 4.5:1，大字按 WCAG 定义至少 3:1。识别控件、选中态和焦点所需的非文本线索与相邻颜色至少 3:1。分别用深、浅主题实际生效的前景和背景计算，对透明色与状态叠层先做合成。验收记录前景、相邻背景、状态及比值。错误、成功、警告与选中使用文字、可识别图形或形状标记辅助区分，并同步相应的可访问名称或 ARIA 状态。 [WCAG 2.2](https://www.w3.org/TR/WCAG22/)

## 间距、形状与布局

- 优先复用 `--ui-space-1` 至 `--ui-space-6`（4/8/12/16/24/32 CSS px）。默认动作间隔 8、组内边距 12 或 16、相邻区块间距 24。设置原语保留现有 6px 行间距和对应内边距。局部图标光学校正、原生尺寸和特定布局尺寸由现有公共样式持有。
- 工具栏紧凑控件按 `--ds-control-size`（28px）。默认独立动作复用 `.btn` 的 30px 基线，输入/选择器在同一排使用同一字段族的高度，通用设置 Select 实际为 34px。正文较大的字段复用 `--ds-field-height`，长文案、放大字体和窄窗允许高度增长。混排需对齐中心，并按组件角色选择密度。
- 基础控件及图标按钮默认 `--radius-xs`（8px），填充字段可沿用公共字段 8–10px 变体。卡片或菜单用 `--radius-md`（12px），现有设置卡片/行用 `--radius-md-plus`（14px）。Composer 复用 `--ds-composer-radius`（20px），开关和已有圆形发送动作使用 `--radius-full`。同一角色选定公共变体后保持一致。
- 可见控件边界默认 1px，悬浮结构按层级使用公共阴影。内流区域以表面和留白分组。卡片、边框和阴影须有明确的分组、边界或层级作用。分割线、滚动或裁切由容器控制，给焦点轮廓、菜单和按钮留出空间。
- 外壳、工作面板和阅读列复用现有布局 Token 和所有者。弹层在视口内约束宽高，长内容内部滚动，保留关闭与提交路径。窄窗先收次要动作、换行或采用原有 overlay；避免挤窄编辑区、遮住焦点或改变业务入口。
- 过渡使用 `--motion-duration-*` 与 `--motion-ease-*`。状态切换保持布局稳定，尊重 `prefers-reduced-motion`，载入状态同时提供静态可理解的反馈。

## 组件规范

相同操作角色跨模块采用同一组样式或已有公共变体，按钮、搜索框、字段和菜单优先复用统一原语。对齐高度、圆角、字体、间距、颜色及交互反馈。先按语义和密度选变体，例如工具栏图标动作与表单主提交各用相应基线。已有多种实现时，核对其业务、权限、平台或密度差异，记录保留理由及适用范围。

公共组件的所有者负责外观、内部结构和交互状态，页面负责外部布局、组合及业务数据、权限、路由和生命周期。功能样式通过已有类、选项或 Token 选择变体，禁止越过组件边界改写内部选择器或用更高优先级压过公共规则。先复用语义 Token，避免硬编码颜色、通用尺寸或为页面维护独立样式体系。缺少公共实现时，先组合原生控件和已有类；需要跨页复用的变体由公共所有者定义一次。

尺寸单位为 CSS px。以下各族统一使用后文状态规则。

| 组件 | 复用与实现标准 |
| --- | --- |
| Button / IconButton | 复用 `.btn`、`.primary`、`.danger`、`.alt`、`.icon-btn` 与现有工具栏变体。文本动作沿用公共横向内边距，同组高度一致。图标按钮默认 28×28、居中，使用可访问名称。提交、取消、危险操作区分角色，危险意图在可见文案中明确。 |
| Input / SearchInput / Textarea | 复用 `.ds-input`、已有表单字段与原生 `input`/`textarea`。字段有可访问标签，placeholder 仅提示；错误与字段关联。搜索组合用同一个外壳承载放大镜、输入及清除按钮，输入和图标基线对齐。多行字段可增高或内部滚动，保留 Composer 自有的输入与发送契约。 |
| Select / Checkbox / Radio / Switch | 短选项复用 `.ds-select` 和原生 `select`。多选/单选优先原生 checkbox/radio 和可点标签，使用主题语义色。即时开关复用 `createSettingsToggle`（38×22 轨道，16px 滑块）；互斥设置可复用 `createSegmentedControl`（26px 项，公共容器）。切换需同步 checked、aria 状态和可见标记。 |
| Dropdown / Menu / MenuItem | 动作菜单复用 `openActionMenu`，复杂选择保留现有 picker/listbox，内容浮层复用 Popover。动作菜单项沿用 32px 最小高度和 8px 间隔，前导图标与末尾快捷键/选中标记对齐。支持方向键、Enter/Space、Escape、回焦；相应角色决定 Tab 行为，分隔线只用于真实分组。 |
| Card / Panel / List | 设置复用 `createSettingsCard`、`createSettingsRow`，工作面板复用现有 surface 所有者。列表复用同行密度与动作位置，主项、状态和次要动作有独立语义；静态卡片没有 hover/pressed 假反馈。行操作悬停出现时须随键盘焦点显示。 |
| Tabs / Badge | Tabs 使用既有 tablist 模式，选中态用可见标记和 `aria-selected`，关联 tabpanel 并支持方向键。设置切换值用 Radio/Segmented。Badge 复用 `createBadge`（20px、11px、6px 圆角），用可读文本表达状态。 |
| Tooltip / Popover | Tooltip 用于简短文本，hover 和键盘焦点可见且可关闭。`title` 只补充非必要信息。交互帮助使用有名称的按钮，支持鼠标点击与 Enter/Space。Popover 由所属浮层入口管理定位、展开状态和关闭，打开时按内容角色保留触发点焦点或将焦点移入。Escape 关闭并回到有效触发点；触发点消失时，焦点移到合理后继。点击外部或 Tab 离开时按角色处理，保留用户正在前往的目标。复用相容的 `openPop` 等入口、公共阴影和有界宽度。 |
| Dialog / Modal | 复用 `openModal` / `confirmModal`，包括独立确认层。对话框有标题、初始焦点、模态 Tab 循环、可用取消路径和关闭后的合理回焦。长正文内部滚动，动作区保持可达，危险确认遵守原确认契约。 |
| Toast / Notification | 复用 `toast` / `showNotice` 和反馈样式。短暂可处理的反馈用 Toast，需要持续关注的阻断、错误及重试放在对应页面或控件旁。按紧急程度选 `status` / `alert`，重复反馈去重，普通成功优先就地反馈。 |
| EmptyState / Loading / ErrorState | 优先复用 [现有反馈样式](../../public/ui4-feedback.css) 和表面内状态区域。按下文状态语义决定显示条件，复用就地文本、可访问状态和恢复入口。 |

常用行为入口位于 [public/ui](../../public/ui/)。 [动作菜单](../../public/ui/action-menu.js) · [浮层](../../public/ui/popover.js) · [弹窗](../../public/ui/modal.js) · [Toast](../../public/ui/toast.js) · [Notice](../../public/ui/notice.js) · [工作区](../../public/ui/workspace-surface.js)

## 交互状态与焦点

| 状态 | 视觉与行为 |
| --- | --- |
| Default | 控件可识别，使用对应的文字、表面及边界 Token。 |
| Hover | 仅可操作项用 `--ds-bg-hover` 或原语对应状态，保持尺寸。 |
| Active / Pressed | 按下用 `--ds-bg-active` 或主动作原语，松开复位。选中、切换、展开另有持续标记与语义。 |
| Focus | 鼠标点击后按钮和菜单保持克制，文本字段可用光标和同一字段边框或背景表达编辑态。 |
| Focus-visible | 键盘聚焦用可见、持久且不被裁切的 `--ds-focus` 指示。按钮、菜单及可点击项默认 2px outline，外偏移 1–2px，滚动容器必要时用内偏移。字段和搜索组合使用一处指示。 |
| Disabled | 真正阻止点击、快捷键和重复提交，原生可用 `disabled`；需留在键盘序列时用 `aria-disabled` 并在事件入口阻止激活。保留可读标签，禁用原因确有行动价值时就近说明。 |
| Loading | 只限制受影响操作，阻止重复触发，保留按钮尺寸与可访问名称，显示进度或短状态。等结果到达后更新语义并按原逻辑恢复焦点或输入。 |
| Error | 用 `--ds-error`、文字或图标显示，字段用 `aria-invalid` 及关联说明。错误保持可见，键盘焦点仍可定位。 |

- 所有交互组件用统一的 `--ds-focus`。每个可聚焦目标只保留一道焦点指示。独立字段可替换原边框，或保留中性底边框并使用一个清晰轮廓。复合搜索框或 Composer 应明确由输入本身还是外壳绘制。外壳负责时，仅在内层输入获得键盘可见焦点时显示输入提示；清除、附件、发送等独立按钮各自显示焦点。键盘聚焦的 textarea 需要持久可见的指示，插入光标只表示编辑位置。
- 在实际样式层叠中检查边框、outline 与阴影。禁止浏览器默认蓝色焦点、旧焦点色叠加、不协调的外发光和全局清空 `outline`。仅在同一目标已有清晰替代指示时收起默认轮廓。用错误文字或标记配合 `aria-describedby` 保留错误信息，避免错误边框与焦点描边叠成双圈。原生控件继续保有原生操作语义；强制颜色模式保留可见指示，必要时用系统色 `Highlight` 回退。
- 用真实 Tab/Shift+Tab、方向键和 Esc 检查正反路径、选中与焦点的区别。菜单或对话框关闭时把焦点还给仍存在的触发项，触发项被移除时移至合理的后继项。原生嵌入视图、粘滞区域和滚动裁切也必须给焦点留出可见空间。[W3C Focus Visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html) · [W3C Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

### 状态语义与反馈

| 状态 | 显示条件与反馈 |
| --- | --- |
| Loading | 当前请求仍在进行。保留布局和可用的已有数据，按需标记 `aria-busy`。 |
| Empty | 读取成功且确实为空，或过滤后没有匹配。区分这两种情况，按需要给出创建或清除过滤的入口。 |
| Error | 读取或操作失败时就地显示可理解的问题和可用的下一步，例如重试。保留可安全恢复的输入和上下文，重要错误持续可见。禁止把失败投影成空列表或成功。 |
| Success | 由业务契约确认操作成功后显示结果，例如更新后的列表或短状态。待同步、未确认与部分完成使用实际状态文字。 |

界面状态取自持有该业务状态的模块。以文件面板为例，确认未选择项目时显示「还没有打开项目」，项目读取失败时显示错误和刷新入口，成功返回空目录时显示空目录。缺少数据或结果未知时，保留其真实语义。

## 内容克制（Content Minimalism）

页面常驻文字服务当前操作。保留核心内容、操作名、数值与单位、当前状态、必要输入要求、缺失/错误及安全提醒。辅助文字只有在能说明用户下一步、避免误操作或解读当前状态时才常驻。危险操作写明对象、影响及可用撤销路径。把复杂教程、背景和限制集中到帮助页或文档；局部补充信息通过带名称的帮助图标点击查看，键盘也能打开。必填条件、修复步骤、风险和无障碍名称随控件保留。

标题下默认无副标题。表单、卡片和列表避免重复说明、固定灰字、无关前提和占位文案。同一状态和术语保持一致，同一作用域内的同一操作保留一个主要入口。确需固定操作栏、键盘入口或不同作用域的操作时，确保各入口有明确价值且动作语义一致。技术栈、文件存储位置、内部字段、原始错误和实现细节留给诊断界面或开发文档。审查时为每条常驻辅助文字回答「它帮助用户完成哪一步、读懂什么状态或避免什么错误」。

## 图标与 PI-Desktop 参考

新增或替换图标，先核对已有同义图标和使用位置，例如 [菜单图标](../../public/ui/action-menu.js)、工具栏及应用内 SVG。已有图标满足要求时直接复用；需要新图形时优先查 IconMCP，并优先选与同组一致的系列和简洁 outline。普通动作以 24×24 viewBox、16px 显示尺寸及相邻组的统一线宽为基准，例如菜单组用 1.6 的源 stroke。绘制时采用 `stroke="currentColor"` 或填充型的 `fill="currentColor"`，对齐线端、视觉比例及中心。图标作为装饰时从无障碍树隐藏，动作名由触发控件提供。品牌、原生窗口按钮等允许沿用各自已建立的样式并记录理由。

选定图标后核查具体图标的来源、系列、名称及实际许可，按许可保留声明。记录来源链接及版本或取得日期，把静态 SVG 纳入本地资源或现有受控图标映射，并在深浅主题核对继承色和对比度。禁止运行时依赖外部图标服务、加载远端 SVG 或把未经核查的 SVG 作为可执行标记插入页面。IconMCP MCP 是开发期可选查找方式，接入按官网说明与开发环境已有授权进行。已有合规图标按需复用，新增依赖遵循仓库规则。 [IconMCP 图标库](https://iconmcp.com/?set=arrows) · [Agent 接入](https://iconmcp.com/agents) · [许可](https://iconmcp.com/licence)

PI-Desktop 用于对照组件一致性、排版密度、按钮和输入体验、信息克制、状态反馈和模块连续性。比较对应任务与信息层级，保留 pi-GUI 自身业务流程、原生窗口与工作面板行为。截图对比须注明来源和尺度，外部视觉资料与源码许可边界按[既有参考档案](pi-desktop-reference/README.md)处理。

## 视觉验收

凡改变用户看到或操作的 UI，包括文案、布局、样式、图标、主题与交互状态，须实际渲染。可用现有离线 `npm run harness` 和真实浏览器；涉及 Electron 标题栏、原生 Browser、系统弹层、隔离凭据窗口、DPI 或打包行为时，使用相应桌面路径取证。使用临时 fixture 并遵循[测试政策](../testing.md#测试执行政策)。纯规范文档按文档验证执行。

| 维度 | 最低覆盖 |
| --- | --- |
| 宽度 × 主题 | 每个受影响界面跑宽屏和窄窗口各自的深、浅主题，共四组。桌面建议使用约 1320×820 与产品最小窗口 700×600，记录实际 CSS 视口与 DPR。子窗口使用自身支持范围，涉及布局断点时加测边界。 |
| 中文与英文 | 在受影响界面验证中、英文代表文本和长标签，至少在窄窗覆盖两者。已有语言切换走产品入口，缺少切换时使用离线夹具呈现中英文数据或文案，明确属于排版检查。 |
| 状态 | 检查 Default、Hover、Pressed、指针 Focus、键盘 Focus-visible、Disabled、Loading、Empty、Error、Success 及对应选中/展开态。按实际组件语义标明不适用项及理由，在深浅主题各验证关键状态。 |
| 可操作性 | 用真实键盘和指针检查焦点、对比度、弹层边界、开关和回焦。对受影响的公共组件，在当前页面与其他有代表性的调用面比较实际尺寸、字体、圆角、间距与状态。检查长内容及字体缩放下的换行、截断、局部遮挡、操作和必要说明。 |

每组记录源码或产物身份、入口、平台/浏览器、视口与缩放、主题、语言或夹具、操作步骤、实测结果和截图位置。瞬时状态可用录屏或实测数据补充代表截图。标明没有运行的检查及原因，按 REVIEW 处置。jsdom、CSS 阅读及旧截图仅能补充当次渲染证据。证据位置及报告按 [开发验收材料](../acceptance.md)。
