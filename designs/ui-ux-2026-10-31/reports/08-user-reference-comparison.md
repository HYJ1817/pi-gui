## 2. 三组直接对照

### 首页

![左：用户 PI-Desktop；右：现有 A 原型](../evidence/reference-user/comparison-home.jpg)

参考应用是一条完整侧栏：会话/项目在上，系统入口在底部；主区顶部只有轻量上下文与少量工具。现有 A 拆成图标栏、会话栏、顶栏和全宽底栏，工作区路径又占一个底部区块，边界显得较多。**关键差距是导航组织与表面层级，不能靠改几个颜色解决。**

U01 左栏占整图约 22.8%；A 的 CSS 为 52px 图标栏 + 248px 会话栏，在 1440px 下共约 20.8%。因此不能简单把问题归因于“左边太宽”，应首先减少重复层级。建议下一轮以一条可折叠侧栏作为对照方案，保留 pi-GUI 原有入口映射，低频操作收进适当菜单。

U01 主区中性炭黑，侧栏近黑，输入框略抬亮。对未经过滤的 PNG 取样：侧栏 `(100,500)` 为 `#000000`，主区 `(700,850)` 为 `#181818`，输入面 `(600,1060)` 为 `#212121`。这是指定像素观测，不能反推出全部主题 Tokens。A 当前 canvas/nav/input 分别是 `#181b20` / `#14171c` / `#252a32`，整体更偏冷蓝，边框和强调色也更抢眼。

参考输入框靠填充色形成主体，圆角柔和，附件/模式/权限在左、模型/发送在右；A 输入区轮廓更强，模型与思考等级挤在左侧，外部还有说明文字及全局底栏，底部信息更碎。后续应统一内外边距和控制区对齐，普通态与 focus-visible 分开处理；保留 pi-GUI 自己的模型、思考等级与能力约束，不照搬参考的权限/模式业务。

空态方面，参考的问候、引导清单、输入区各有明确位置；A 额外堆叠三个建议按钮与能力说明。下一轮应先突出项目上下文和输入任务，辅助引导按实际配置状态出现，不复制参考吉祥物，也不把其“添加服务/保存密钥”直接当作 pi-GUI 前置条件。

### 设置

![左：用户 PI-Desktop 常规设置；右：现有 A 设置](../evidence/reference-user/comparison-settings.jpg)

**这一组差距最大。** 参考进入设置后，左侧直接成为带搜索的分类导航，主区是标题、分组、成行的标签与控件；会话列表退出当前视图。A 仍保留图标栏和项目会话栏，主区再嵌套分类栏，形成额外导航层。

A 外观页仅演示主题与减少动态效果，模型/更新等页也属于简化示意；不能称为覆盖全部设置的信息架构。建议设置作为独立目的地，使用设置分类替换会话栏，保留返回工作区入口；返回时草稿、滚动、运行状态仍由原有 owner 恢复。分类来自 pi-GUI 当前真实能力，不新增参考中的实时语音、云同步、远程主机等菜单。

参考页以背景面区分设置行，不是每行画一条硬分隔线；标题、分组标题、标签、说明和控件层级稳定。A 更接近带分隔线的演示表单，说明与实际控件不够完整。下一轮应以真实设置字段填充并验证长标签、未配置、保存中、保存失败和重试状态。参考部分行和空态也偏高，不必逐项复制其高度与留白。

### Skills / 资源管理

![左：用户 PI-Desktop 技能；右：现有 A Skills](../evidence/reference-user/comparison-skills.jpg)

参考有“范围筛选—搜索—项目上下文—操作”的工具栏，并区分内置、全局、项目；资源行包含名称、说明、来源、状态。A 只有 tabs 与三条示意数据，**内容量与状态复杂度不足以检验真实资源管理页面**。

可借鉴统一资源行与工具栏，但 pi-GUI 的 Skills、Extensions、MCP、Capabilities 各有不同合同：不能把“已加载/已启用/未加载/未知/不可信”都压成一个开关。市场双列卡片适合浏览发现，已安装列表适合密集管理；pi-GUI 没有对应能力时，不添加“市场安装”等假入口。参考中的内置插件、子智能体模板与工具清单也不直接移植。

## 3. 下一轮设计调整优先级

这里的 P0 表示设计方案定稿前必须解决，P1 表示视觉和内容补齐；不是生产故障严重性。

| 优先级 | 当前差距及影响 | 下一轮原型动作 | 验收依据 |
| --- | --- | --- | --- |
| P0 | 图标栏+会话栏+全局底栏分散注意力；设置又加分类栏 | 主工作区对照单侧栏，设置切换为专用分类栏；审查 60 项入口映射 | 每个真实功能有明确目的地；无重复常驻入口；返回会话恢复上下文 |
| P0 | A/B 主要只改变密度和阅读宽度，结构差异不足 | 将中性灰、单侧栏方向作为新对照；现有 A 保留作历史比较 | 同内容、同主题、同 CSS 尺寸重新截图，比较结构而非只换皮 |
| P0 | 设置与资源页示意过少，掩盖内容密度与状态问题 | 按现有源码补齐有代表性的真实字段形状、长描述、来源和能力状态 | 原有功能映射逐项核对；已演示和仅规划入口分开标注 |

| P1 | 输入区外围信息碎，控件优先级不够清楚 | 一体化输入表面，稳定两层布局，模型与发送区明确对齐 | 多行、附件、不同长度模型名、运行/停止/失败在固定宽度下不跳动 |
| P1 | 标题和说明层级偏弱，设置行形态不统一 | 明确页面标题/分组/标签/说明四级，减少硬分隔 | 同 DPI 同 viewport 实看；长中英文和 125/150% zoom 不遮挡 |

## 4. 能借鉴与不能直接沿用

可以借鉴：中性表面、单侧栏、克制的顶栏、统一设置行、资源工具栏、来源分组、右面板共享布局节奏、空态提供下一步。

仍需改良：模型空态同时出现顶部和中心“添加服务”，操作重复；MCP 两个大空态可在数据少时进一步压缩；长英文说明大量省略，需要实际详情或可访问补充。截图未显示其 tooltip 或详情行为，因此不判定其不存在。

不照搬：品牌标识、吉祥物、参考产品市场内容、智能体/规划/目标模式、权限模式、语音、云同步及远程主机；先核对 pi-GUI 是否已有相应能力。所需的模型和思考等级选择继续遵守 pi-GUI 既有合同。
