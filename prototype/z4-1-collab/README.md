# Z4-1 隔离原型：协同编辑数据层

本目录是 Z4-1 设计任务的隔离原型，**不是生产模块**：不接入 `server/`、`public/`、
生产启动入口，也不在 `package.json` 的 npm test 链内。设计说明见
`docs/Z4-1-collaborative-editing-design.md`。

## 文件

| 文件 | 内容 |
|---|---|
| `collab-doc.js` | 数据层（纯数据 + 纯函数）：文档模型、闭集操作 schema、事务化批量应用、幂等日志（opId + 键序无关的内容指纹，FIFO 500 条）、Agent 建议（预览/接受/拒绝，归属校验先于幂等快捷路径）、撤销/重做（逆操作按批次逐步模拟的真实修改前状态生成；`edge.update` 支持 `label: null` 清除以保证可逆）。除 `node:assert` 之外的依赖为零，无 DOM、无 IO、无网络 |
| `collab-test.mjs` | 49 项数据层测试：任务验收点 12 项（编号 1–12）+ 验收修复新增的批次预览/撤销（13）、建议幂等身份（14）、反序列化上限（15）、指纹键序无关（16） |
| `README.md` | 本文件 |

## 独立复核方法

```bash
node prototype/z4-1-collab/collab-test.mjs
```

### 本轮验收修复记录（对应验收 HEAD 72cf5dd 之后的意见）

1. 批次预览与逆操作改为按批次逐步模拟生成（修复「先新增节点/连线、再修改它」时
   预览抛 TypeError、撤销失败）；`edge.update` 支持 `label: null`，使「无 label 连线
   加文字后撤销」可精确恢复为无 label。
2. `acceptProposal` 的归属与 schema 校验移到幂等快捷路径之前。
3. `deserialize` 补齐节点/连线数量上限、连线 ID 唯一、同向重复拒绝、输入体积上限。
4. 操作指纹改为递归键排序的规范化序列化，与属性插入顺序无关。

## 验证边界（防过度宣称）

- 以上全部是**数据层**验证：不涉及任何 GUI、排版、交互或真实窗口。
- 未接入生产代码，`npm test` 不包含本目录；本原型的通过结论不构成生产集成证据。
- 测试全部使用内存构造的文档，不读写用户真实数据（符合 AGENTS.md 硬约束）。
